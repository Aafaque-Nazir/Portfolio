# Strict Writing Style: No Fancy Jargon or Buzzwords

## Core Principle
Always write in clear, human, direct, pragmatic, and professional English. Never use corporate buzzwords, pretentious vocabulary, marketing hype, or AI clichés across any part of this portfolio (code, UI, blog posts, metadata, or documentation).

## Forbidden Words and Phrases
Do NOT use the following words or phrases in any user-facing text, blog content, metadata, or code descriptions:
- **Bespoke** -> Use *custom*, *tailored*, or *built from scratch*
- **Sub-second** -> Use *fast*, *quick*, or *under 1 second*
- **Frictionless / Seamless / Seamlessly** -> Use *smooth*, *clean*, *easy*, or *reliable*
- **Architecting / Leveraging / Spearheading** -> Use *building*, *designing*, *writing*, or *using*
- **Paradigm shift / Paradigm** -> Use *major shift*, *pattern*, or *approach*
- **Cutting-edge / State-of-the-art / World-class** -> Use *modern*, *current*, or *high-quality*
- **Game-changing / Transformative / Revolutionary** -> Use *practical*, *effective*, or *useful*
- **High-converting** -> Use *high-performing*, *effective*, or *fast*
- **Moat / Moats** -> Use *competitive advantage*, *lock-in*, or *differentiation*
- **Synergy / Synergistic / Holistic / Turnkey / Robust** -> Describe the actual feature directly instead of using empty buzzwords
- **Delve / Delving / Testament to** -> Use *explore*, *look into*, or *proof of*

## Tone Guidelines
- Talk like a pragmatic senior engineer speaking directly to a client, founder, or peer engineer.
- Be honest, grounded, and concise.
- Focus on real problems, real solutions, and clean code.
